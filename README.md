# 더파이팅 (THE FIGHTING) — Anime Boxing (Three.js) · 4인 난투 / 방코드 멀티

브라우저에서 바로 실행되는 2.5D 애니메이션 스타일 3D 복싱 액션 프로토타입.
핵심은 **뎀프시롤**(∞ 궤적 스웨이 + 연속 훅), **다중 잔상**, **타격 순간의 카메라·사운드·자막 동시 폭발**, **카운터 시 두개골 진동 연출**.

## 실사 렌더링 기반 — 검증용 PHASE 1

HTTP 서버에서 `index.html?photoreal=1`로 새 렌더링 모드를 실행한다. 직접 제작한 HDR 환경맵·접지 그림자, PBR 재질, N8AO와 선택적 블룸, 4단계 화질 및 동적 해상도를 포함한다. `?profile=1`은 기존 렌더링의 비교 측정을 위한 주소다. 우측 하단 **그래픽 · 측정**에서 화질을 바꾸고 프레임 측정 JSON을 저장할 수 있다.

**아직 실사급 리마스터 완료본이 아니다.** WebGPU, CSM, 실사 캐릭터 에셋과 실제 기기 성능 검증이 남아 있어 기본 렌더링은 기존 모드다. 직접 제작한 에셋 출처는 [ASSETS_LICENSE.md](ASSETS_LICENSE.md)를 참고한다. 새 모드는 HTML 옆의 `assets/`와 HTTP(S) 실행이 필요하다.

## 실행

**배포/실행 파일 = `index.html`** — `dev.html` + `js/*.js` 를 `python3 build_standalone.py` 로 합친 **단일 번들**. 모듈을 개별로 받지 않으므로 캐시에 구버전 모듈이 섞이는 문제가 원천적으로 없다.
**개발**: `dev.html` 을 서버로 열면 `js/` 모듈이 그대로 로드된다. 수정 후 반드시 `python3 build_standalone.py` 로 `index.html` 재생성.

개발용(모듈 분리 버전)은 ES Module + import map 을 쓰므로 간단한 정적 서버가 필요하다 (file:// 불가).
`python3 serve.py 8787` 을 권장 — `Cache-Control: no-store` 를 붙여 배포 후 구버전 모듈이 캐시에 남지 않는다. (처음 한 번은 Cmd+Shift+R 강력 새로고침)

```bash
cd dempsey-boxing
python3 -m http.server 8787
# → http://localhost:8787
```

(또는 `npx serve .`, VS Code Live Server 등 아무 정적 서버.)
Three.js 는 jsDelivr CDN(`three@0.170.0`)에서 로드된다. 첫 화면에서 아무 키/클릭 → 오디오 컨텍스트 활성화 후 시작.

## 멀티플레이 (방코드)

- **솔로**: 나 + CPU 3명 난투.
- **방 만들기**: 5자리 코드 생성 → 친구가 **참가**에 코드 입력. 최대 4명, 빈 자리는 CPU. 방장이 Enter/시작.
- 구조: **호스트 권위 스타형**. 방장 브라우저가 전원 시뮬레이션, 클라는 입력(3개 숫자)만 60Hz 전송, 방장이 20Hz 스냅샷(위치/포즈/상태 + 히트·사운드·자막 이벤트)을 브로드캐스트, 클라는 스냅샷 2개를 보간해 렌더. 서버 없음 — PeerJS 공용 브로커(시그널링) + WebRTC 직결.
- ICE: Google/Cloudflare STUN + 공개 TURN(openrelay.metered.ca) 폴백 — 대칭 NAT(모바일 데이터망)에서도 붙는다. 회사망에서 여전히 안 되면 `Net.js` 의 `iceServers` 에 자체 TURN 추가.
- 데이터채널은 **비순서(unordered)** — 손실 패킷을 기다리느라 뒤가 막히지 않는다. 대신 입력/스냅샷에 시퀀스(`q`)를 붙여 늦게 온 옛 패킷은 버린다.
- 게스트 입력은 바뀐 프레임에 즉시 + 50ms 키프레임. 호스트는 프레임 사이에 눌렸다 풀린 키(`InputState.setNet`)를 다음 시뮬 프레임에 반드시 한 번 '눌림'으로 본다 (짧은 탭 유실 방지).
- 접속 12초 타임아웃 → 새 Peer 로 3회 재시도 → 안내. 시그널링 끊김은 자동 `reconnect()` (화면 복귀/온라인 이벤트에서도). 재연결 중 `unavailable-id` 는 **같은 코드로** 계속 재시도 (코드가 바뀌면 게스트가 옛 코드로 붙다 "접속 중…" 에 갇힌다).
- **하트비트** 1초/8초 타임아웃 (양방향) + ICE failed 감지. WebRTC 만으로는 상대 탭 종료·화면 꺼짐을 30초+ 지나야 알아챈다.
- 게스트 연결이 끊기면 **먼저 같은 방장에게 재접속**하고, 방장 ID 가 서버에 없을 때만(peer-unavailable) 승계한다. 전에는 무조건 승계로 가서 살아 있는 방장과 코드를 다투다 새 방을 파 버렸다.
- 경기 **진행 중** 참가는 거절(`full/playing`), 결과 화면이면 받아 주고 `restart` 때 합류한다.
- **인앱 브라우저(카톡·라인·인스타 등)는 WebGL2 가 안 떠서 `Error creating WebGL context` 로 게임이 뜨지 않는다.** 부트스트랩이 미리 감지해 "Chrome/Safari 로 열기"(카톡 `openExternal`, 라인 `openExternalBrowser=1`, Android intent) 안내를 띄운다. 게스트가 초대 링크로 못 들어오면 십중팔구 이 경우.
- 참가한 사람끼리만 시합 (2~4명, CPU 없음). 게임 중 이탈자는 다운 처리. 재시작(R)은 방장만.
- **채팅**: Enter → 입력 → Enter 전송 / Esc 닫기 (로비·게임 중 모두). 방장이 중계.
- HUD 카드마다 상대의 뎀프시 게이지/MAX 차지도 표시.

## 음성 (VoiceManager)

- `assets/voice/manifest.json` 이 있으면 파일 재생 (캐릭터별 `mashiba:grunt` 식 분리 가능, 배열이면 랜덤). 자세한 건 `assets/voice/README.md`.
- 파일이 없으면 브라우저 일본어 TTS 가 자막 대사를 캐릭터별 피치/속도로 외치고, 펀치 기합·피격 신음은 포먼트 합성음.
- `V` 키: FILE → TTS → OFF 전환. macOS 는 시스템 설정 > 손쉬운 사용 > 음성 콘텐츠에서 일본어 남성 음성(Otoya/Hattori) 을 받으면 더 어울린다.
- 원작 애니 음성은 저작권 자료 — 개인 사용 범위에서만.

## 읽기/밸런스
- 모든 펀치는 전체 시간의 30%가 예비동작(와인드업), 시작 순간 글러브가 흰색으로 번쩍인다 → 보고 가드/저스트 가드.
- AI 공격 간격 0.85~1.65초(공세 시 0.5~1.3), 콤보 최대 3타, 크로스 카운터 22%.

## 코치 말풍선 / 추가 연출

- 호스트가 각 사람 파이터의 상황(연속 피격, 헛스윙 3회, 상대 스태거, 게이지, MAX 차지, 저체력, 쓰러진 상대 가격)을 판단해 코치 대사를 고르고, 해당 플레이어 화면에만 말풍선(일본어 + 한글) + 저음 TTS + 호루라기.
- 쓰러지는 중(1.2초)인 상대도 계속 타겟/타격 가능 — 데미지 없이 몸이 돌며 날아간다. 코치: 「もういい！ 倒れてるだろッ！！」
- 주먹 땀방울 궤적, 피격 캐릭터 붉은 플래시, 글러브 스쿼시, HP 카드 흔들림, 2차 카메라 진동, 스윕 판정 + 머리/보디 부위.

## 성능
- 안 보이는 잔상 리그는 씬에서 분리(행렬 갱신 제외), 관중 360명·2프레임마다 갱신·할당 0, 포인트라이트 제거, 그림자맵 1024/PCF, 후처리 패스는 필요할 때만 활성, 블러 8탭, 픽셀비 최대 1.25, HUD 30Hz.
- **적응형 화질**: 평균 프레임 24ms 초과 시 자동 하향(HIGH→MID→LOW: 픽셀비·그림자·잔상 수·후처리), 13ms 미만이면 복귀. `Q` 로 수동 순환.
- 실측(맥 내장 GPU, 4인 풀 렌더): 평균 8.6ms/프레임, 씬 오브젝트 ~1000, 8경기 연속 후 메모리 52MB 안정.

## 등장 연출 / 카운트다운
- 로비에서 닉네임 옆 **자기소개 한마디**(40자) 입력 → 시작 시 선수별 3.6초: 코너에서 달려 나와 삿대질 → 양팔 들어올리기, 이름 배너 + 자기소개 자막(TTS). 담당 코치도 같이 외침.
- **Space / Enter / 클릭 = 스킵** (클라는 방장에게 요청 → 전원 동기). 스킵 또는 종료 후 각자 자리에서 **3·2·1 카운트다운(비프)** → **공(종) 2타 + FIGHT!** 와 함께 조작 개방.
- 인트로/카운트다운 중엔 시뮬·입력·스냅샷 모두 정지. 모든 클라가 로컬로 같은 타임라인을 재생하고, 방장이 phase 메시지로 동기화.

## 로프 반동
- 로프 쪽으로 계속 밀면(2.5m 밖) 로프가 늘어나며 최대 0.45초 충전 → 놓거나 다 차면 안쪽으로 발사 (2~8.5 m/s), **부스트 0.6~1.4초**: 이동 1.45배·펀치 위력 1.3배, 발밑 불꽃. 0.12초 미만 스치기는 무시, 발사 후 1초 쿨. 넉백으로 로프에 부딪히면 절반 속도로 반사.
- 거리감 보조: 내 발밑 **리치 링**(사거리 반경, 상대가 안이면 붉게) + 상대까지 바닥선. 카메라는 더 높은 부감(높이 2.9m).

## 조작

| 키 | 동작 |
|---|---|
| `W A S D` | 이동 (카메라 기준) |
| 기 게이지 | **때려서만 찬다** (훅 8 · 스트레이트 6 · 플리커 4 · 고유기 12, 카운터 ×1.5, 가드당하면 40%, 맞으면 +2.5). 100 → **MAX** |
| `J` / `K` | 왼쪽 / 오른쪽 펀치. 뎀프시롤 중엔 **몸이 기울어진 방향**이 훅 방향을 결정하고, 키를 누르고 있으면 좌우 끝마다 훅이 자동 연결된다 |
| `L` (또는 J+K 동시) | **필살기** — 맞고 살아남은 상대는 **다운**(넘어짐 → 누움 → 고개 흔들며 기상, 2.7초 무적·행동불가). 속공형 미야타 졸트 블로는 다운 대신 스태거. **필살 훅** — MAX SPEED 중에만. MAX 를 오래 유지할수록 차지 ×1~×3 (위력↑). 게이지 전부 소모. **슈퍼아머**: 발동~적중까지 맞아도 안 끊김 (데미지 50%) |
| `SHIFT` | 가드 — 필살기·카운터 포함 모든 공격을 막음. 칩 데미지 4%(필살기 8%, 최소 0.3)만 들어옴. 4초 이상 가드만 하면 코치가 잔소리 |
| `R` | 재시작 |

**뎀프시롤 중 연타**: J/K 를 누르고 있으면 좌우 끝마다 자동 훅, 연타하면 입력 버퍼로 끊김 없이 이어진다. MAX 가 아닐 때 강한 펀치를 맞으면 롤이 끊기거나 게이지가 깎인다.

**상대 AI (극한)**: 플레이어 펀치를 읽어 **블록**(느린 훅일수록 잘 막음, 맞을수록 읽기 능력↑) → 블록 후 65% **가드 카운터**, 스트레이트에 30% **크로스 카운터**(플레이어 스태거 + 골 흔들림) / 슬리핑, 필살기(차지 ×3 미만)엔 45% **백스텝 회피**. 블록 중 5연타면 **가드 브레이크**. 4연 콤보, 피격 직후 55% 즉시 반격, 시간이 지나면 **자체 뎀프시롤**(3.6~4.8초, 좌우 끝마다 훅 연속). 스태거는 6연타 또는 카운터에만 걸리고 짧으며 회복 후 4초 면역.

**카운터**: 상대가 플리커 잽을 내는 도중(와인드업~스트라이크)에 훅이 꽂히면 카운터 판정 → 데미지 ×2.2, 강제 스태거, 히트스톱 170ms + 슬로모션, 머리 고주파 진동, 상대 다중 잔상, 화면 지터/이중상, 「カウンター！！」 자막, 이명(耳鳴り) 사운드.

## 뎀프시롤 움직임 구성 (DempseyController.applyToPose)

단일 `sin` 이동이 아니라 위상 θ 하나에서 파생된 여러 성분이 연결된다.

- 골반 좌우 스웨이 `0.3·sinθ` + 무게중심 하강 + 좌우 끝에서 추가 딥 `(1−cos2θ)/2`
- 허리: 앞으로 숙임 + 비틀림 `0.85·sinθ` + 측면 기울임 `−0.52·sinθ`
- 가슴(어깨) 추가 비틀림 / 기울임
- 머리: 오프셋 `(0.11·sinθ, 0.07·sin2θ)` → ∞ 궤적, 시선 유지를 위한 역회전
- 다리: 크라우치 + 체중 실린 쪽 무릎 더 굽힘 + 발 미끄러짐 보정
- 팔: 기울어진 쪽 팔꿈치를 뒤로 → 훅 장전 → `Punch.js` 훅 키프레임이 그 위에 덮임
- 속도(강도) 상승 → 진폭·각속도·잔상 개수/간격·집중선·드론 피치·카메라 근접 모두 함께 증가

## 타격 순간 (Game.onHit)

히트스톱 50~100ms(시뮬레이션 dt ≈ 0, 카메라/2D FX는 실시간 진행) + 카메라 킥/줌/셰이크 + 화이트 플래시 + 임팩트 링/버스트 + 의성어 + 방사형 블러 + impact/bass 사운드 + 자막/대사 + 관중 환호가 같은 프레임에 발화한다.

### 연출형 필살기와 가드
가드(SHIFT) 중인 상대에게는 **연출형 필살기도 막힌다**: 시전 자체가 무산되고 칩 데미지(총량의 8%)만 들어가며, 시전자는 0.7초 경직 + 게이지 소모. "가드!!" 팝업 + 가드 충격 연출. 카페 돌격은 시전은 되지만 가드 중인 상대는 밀리지 않고 도트의 12%만 받는다.

필살기 연출은 `js/Ultimate.js` 가 3D 소품을 실제로 생성/애니메이션하고, 연출 동안 카메라가 전용 와이드 샷으로 전환된다 (낙하물이 화면에 확실히 보이도록). 데미지는 연출 시간에 걸쳐 나눠 들어가고(총 34+7×차지 ×파워), 끝나면 상대가 쓰러진다.

등장 연출도 전용: 채채더킴 브이 + "난 문화생활을 좋아해~", 쩡효 바벨 들었다 던지며 "3대 500 미만 대화 금지.", 뼈석원 배 문지르며 "난 먹어도 살 안 쪄." + 부릉부릉.

## 인트로 스킵 (전원 동의)

## 음성 (성별 구분)
캐릭터 정의에 `gender`('m'/'f') 가 있고 `js/VoiceManager.js` 가 이를 따른다.
- **TTS**: 언어(ja/ko)별로 남성/여성 음성을 따로 골라 쓴다(이름 기반 판별 — Hattori/Otoya·Kyoko/O-Ren·유나 등). 한쪽 성별 음성이 없는 OS에서는 같은 음성을 쓰되 **피치로 보정**(반대 성별이면 ×1.45 / ×0.6).
- **합성 기합·신음**: 여성은 기본 주파수 ×1.55, 포먼트 ×1.18 로 올려 남녀가 확실히 구분된다. (예: 이포 297Hz, 채채더킴 532Hz, 오승현 588Hz, 정주원 178Hz)
- 코치는 항상 남성 음성 + 낮은 피치.

## 후처리 (PostFX) 구조 — 2026-09 개편
EffectComposer(Render→Afterimage→SpeedBlur→Output, 최대 4패스) 를 걷어내고 자체 렌더타깃 파이프라인으로 교체했다.
1. scene → `rtScene`
2. 잔상이 필요할 때만 `rtScene + rtPrev → rtAccum` (핑퐁)
3. 블러/수차/비네트/열왜곡/지터/이중상 **+ 톤매핑 + sRGB** 를 한 패스로 합성해 화면에 출력
평상시 렌더 콜 **2회**, 잔상 켜질 때 3회 (기존 3~4회). 품질 0/1/2 는 블러 탭 수(8/4)와 잔상 on/off 로 조절.
주의: three 는 ShaderMaterial 프래그먼트 프리픽스에 tonemapping/colorspace `_pars` 를 이미 넣어 주므로 셰이더에서 다시 `#include` 하면 함수 중복 정의로 컴파일이 깨진다 (`_fragment` 청크만 넣을 것).

## 링 크기

## 멀티플레이 연출 동기화 (중요)
호스트 전용 로직에서 만든 연출 이벤트는 **스냅샷의 `ev` 배열**로만 클라에 전달된다. `onSnapshot` 에 해당 `t` 를 처리하는 분기가 없으면 게스트 화면엔 그 연출이 아예 안 나온다 (과거 `ult`/`ultblk`/`rush` 가 그랬음).
또 클라는 파이터 시뮬을 돌리지 않으므로 `ultT` 같은 연출 상태가 없다 → `ult` 수신 시 클라에서 직접 세팅하고 `renderFrame` 에서 감쇠시켜야 연출 카메라가 동작한다.
새 연출을 추가할 때 체크: ① 호스트에서 `pendingEvents.push` ② `onSnapshot` 에 분기 추가 ③ 카메라/타이머 등 클라 상태 보정.

## 게스트 버벅임 대응 (넷코드)
문제: 게스트만 끊겨 보임. 원인은 ① 도착 시각 기준 보간(지터가 그대로 튐/멈춤) ② 20Hz 스냅샷 ③ 내 캐릭터도 서버 왕복을 기다림.
- **지연 재생 버퍼**: 서버 `ts` 기준으로 `delay = 스냅샷 간격×2 + RTT/2` (70~220ms) 만큼 늦게 재생. 재생 시계를 ±12% 범위에서 미세 가감속해 지터 흡수, 400ms 이상 어긋나면 점프.
- 스냅샷 버퍼 3 → 10개, **25Hz** 로 상향.
- **내 캐릭터 로컬 예측**: 입력을 즉시 반영(오프셋 누적, 최대 0.7m)하고 0.35초 시정수로 서버 위치에 수렴. 게스트도 이동이 즉각 반응한다.
- 스냅샷 정밀도 축소(포즈 소수 2자리) → 2인 기준 616B/스냅샷, 약 15KB/s.
- `PING`/`BUF` 를 화면 좌하단 netinfo 에 표시(클라 전용)해 현장에서 원인 파악 가능.
- **입력 예측(동작)**: 게스트가 J/K/U/I/L 을 누르면 그 프레임에 팔 동작을, SHIFT 는 가드 포즈를 **먼저 그린다**. 호스트 포즈가 도착하면 예측은 즉시 버린다(겹침 없음). 판정·데미지는 여전히 호스트 권위.
- **지터 적응형 지연**: `간격×1.15 + 지터×2.2 + RTT×0.25` (38~200ms). 회선이 깨끗하면 버퍼가 40ms 아래로 내려간다.
- 스냅샷 **30Hz**.
실측(로컬 2탭): 펀치 입력→화면 반영 **21ms**, 가드 **9ms**, 버퍼 34~42ms (개선 전 82ms).
남은 카드: PeerJS binary 직렬화, 델타 압축(변경된 필드만), KO 된 파이터 포즈 생략.

## 맵 / 규칙 선택
시작 화면과 **로비 안** 양쪽에 **맵**(복싱 링 / 암벽)·**규칙**(난투 / 2:2 팀전) 토글이 있다 (localStorage `dr-map`, `dr-rule`). 방을 만든 뒤에도 방장이 바꿀 수 있고, 변경 즉시 `lobby` 브로드캐스트로 게스트 화면도 갱신된다(게스트는 읽기 전용 표시). 시작할 때 `start` 메시지에 맵이 실려 전원이 같은 맵을 연다.
팀전이면 로비 명단이 **청코너 / 홍코너** 두 칸으로 갈라지고(짝수 좌석=청, 홀수=홍), 경기 중 HUD 카드도 팀 색으로 표시된다.
**좌석(seat) 개념**: 네트워크 슬롯(netSlot, 접속 순서로 고정)과 화면상의 자리(seat, 팀·스폰 결정)를 분리했다. `this.seats[seat] = netSlot`.
방장은 명단에서 선수를 **드래그앤드랍**해 자리를 바꾼다 — 사람이 있는 칸에 놓으면 **서로 교환**, 빈 칸에 놓으면 이동. 변경은 즉시 게스트에게 브로드캐스트되고, 시작 시 cfg 가 좌석 순서로 만들어진다(`team = seat % 2`).

### 암벽 맵 (`js/Cliff.js`)
반경 ~6.2m 의 울퉁불퉁한 바위 고원. 로프가 없고 **가장자리를 넘으면 낙사**한다(붉은 경고 링 표시).
- `setArena({kind:'cliff', radius})` 로 Fighter 에 경계를 주입. 링일 땐 기존 로프 반동, 암벽일 땐 추락 판정.
- 추락: 1.5초간 허우적대며 가속 낙하 → KO. 낙하 높이(`fallY`)는 스냅샷으로 동기화.

### 2:2 팀전
슬롯 짝/홀로 팀이 갈리고(멀티는 4명 필수), **한 팀당 1명만 링 위**에 선다. 쓰러지면 2.2초 뒤 같은 팀 다음 선수가 **풀피로 교대** 입장("교대다—!" + 공 소리). 두 명 모두 쓰러진 팀이 패배(`TEAM n WIN`).
- 대기 선수는 시뮬레이션·판정·타겟에서 완전히 제외(벤치에서 낙사하던 버그 수정), 스냅샷 플래그(512)로 클라에도 동기화.
- 타겟 선정은 같은 팀을 제외한다(난투 모드는 `team: null` 이라 영향 없음).
- 솔로에서도 2:2 가능: 나 + CPU 파트너 vs CPU 2명.

- **다운/KO**: 앞이 아니라 **뒤로 벌러덩** 넘어진다.
- **잔상**: 이동·걷기엔 남지 않고 **공격/필살기 중에만** 남는다.

- **낙사**: 2.4초 동안 중심을 잃고 회전하며 추락(팔다리 허우적), 카메라가 떨어지는 선수를 따라 내려간다.
- **체격 70%**: 모든 파이터 스케일 0.7, 히트박스·리치·간격·카메라 거리도 같은 비율로 조정.

- **쩡효 필살 각도**: 랙이 시전자를 바라보게 회전하고 피격자도 정면 정렬 → 바벨이 몸을 가로지르던 십자 교차 해소.
- **최적화**: 맵 지오메트리 `matrixAutoUpdate=false` 로 고정(매 프레임 행렬 갱신 제거).

## 버그 수정 기록 (팀전 / 암벽)
- **갈라진 땅에서 안 떨어짐**: 붕괴 섹터의 발판 판정이 조각이 완전히 사라진 뒤(`gone`)에야 0 이 됐다 → **떨어져 나가기 시작한 순간(`falling`)부터 0**. 또 KO 상태에서는 낙사 판정을 건너뛰어 시체가 허공에 서 있었다 → KO 여부와 무관하게 판정.
- **차례가 아닌데 서 있음**: 쓰러진 선수가 무대에 계속 남아 있었다 → 팀전에서는 KO 연출(2.2초) 뒤 **무대에서 퇴장**(벤치 처리, 멀티는 `out` 이벤트로 동기화). 무대 인원은 항상 팀당 1명.
- **다음 차례가 죽기 전에 나옴**: 교체 타이머가 KO 즉시 돌았다 → **쓰러진 선수가 실제로 퇴장한 뒤에만** 타이머 시작 (KO→퇴장 2.2초 → 교체 2.2초, 총 4.4초).
- **등장씬에 2번 주자가 안 보임**: 벤치 선수는 숨겨져 있어 인트로에도 안 나왔다 → 인트로 동안 **전원 표시**하고 인트로가 끝나면 다시 벤치 처리.
- **팀킬(오사)**: 팀전에서 같은 편이 타격 판정에 포함돼 있었다 → `sameTeam()` 으로 히트 판정·타겟 선정·카페 돌격 모두에서 같은 편 제외 (난투는 `team === null` 이라 영향 없음).
- **대기 중인데 내가 무대에 있는 것처럼 보임**: 카메라(viewPair)와 로컬 예측이 벤치 여부를 무시했다 → 대기 중엔 **무대 위 같은 팀 선수를 관전**하고, 입력 예측/이동 예측을 끈다. `대기 중 — 아군이 쓰러지면 교대로 출전합니다` 배너 표시.
- **팀 판정 누락 보정**: 팀전인데 일부 선수의 `team` 이 비어 있으면 같은 편도 타격 대상이 됐다 → 경기 구성 시 좌석 순서로 팀을 메우는 안전장치 추가.

## 멀티 동기화 점검 (2026-09-15)
스냅샷(30Hz)에 실리는 것: 위치/야우/루트 X회전/공중높이/**낙하높이(fy)**/HP/포즈 29개/게이지·차지/펀치 진행도/타겟/쿨다운 + 비트 플래그(ko, 스탠스, MAX, 가드, 스태거, 필살, 부스트, 로프, 다운, **벤치(512)**, **낙하(1024)**).
이벤트(스냅샷 `ev` 배열): `hit, a(오디오), s(자막), fin, coach, rope, ult, ultblk, out(퇴장), sub(교체), rush`.
확인/수정한 것
- 낙하 중·KO·다운·벤치 상태에서는 **로컬 예측을 끈다** (예측이 떨어지는 몸을 끌어올리거나, 대기 중인데 움직이던 문제).
- 클라도 `falling` 플래그로 낙하 상태를 안다.
- 팀·벤치 상태는 cfg + 플래그로 이중 동기화. 4탭 실측: 팀 `[0,1,0,1]`, 벤치 `[F,F,T,T]`, 가시성 `[T,T,F,F]` 호스트/게스트 일치.
- 대기 중인 게스트는 같은 팀 선수를 관전하고(시점 slot 1), 키를 눌러도 이동 0, 대기 배너 표시.

### 동기화 잔여 이슈 해소
- **스태거 지속시간 동기화**: 스냅샷에 `st`(남은 초) + `sk`(normal/liver/groggy) 추가. 예전엔 on/off 비트만 보내 클라가 1초로 가정했다.
- **예측 게이트**: 클라 예측이 호스트의 수락 조건(`busy`, 펀치 캔슬 구간, U/I 쿨다임, L 게이지 MAX, 벤치/낙하)을 그대로 검사한 뒤에만 그린다. 거부될 입력은 아예 예측하지 않는다.
- **잔상 크기**: 잔상 리그가 본체 축척(0.7)을 덮어써 원래 크기로 보이던 버그 수정 (`FIGHTER_SCALE` 곱).

## 캐시 문제 (중요)
GitHub Pages 는 HTML 을 최대 10분 캐시하고 브라우저도 index.html 을 캐시한다. 번들이 index.html 안에 있으므로 **새 배포를 해도 구버전이 계속 돌 수 있다** (버그 수정이 반영 안 된 것처럼 보임).
대응: 빌드마다 `version.json` 과 페이지의 `window.__BUILD_ID` 를 갱신하고, 로드 시 + 1분마다 `version.json?ts=`(no-store)로 비교한다.
- 첫 불일치면 **자동으로 한 번 새로고침**(`?v=<build>` 로 캐시 우회), 이후에는 우측 하단 `새 버전이 있습니다` 배너를 눌러 갱신.

### 치명 버그: 필살기 후 팀 정보가 날아감
연출형 필살이 끝나는 블록에 예전 일괄 치환이 잘못 들어가 `this.armor = 0;` 자리가
`this.fallT = 0; this.fallY = 0; this.benched = false; this.team = null;` 로 덮여 있었다.
그 결과 **필살기를 쓴 사람의 `team` 이 null 이 되어** ① 아군 판정이 풀려 팀킬이 가능해지고 ② 그 팀에 "출전 선수 0명" 으로 보여 **교체 선수가 튀어나왔다**. (아머 해제도 누락)
수정 후 7개 캐릭터 필살을 각각 7초씩 돌려 검증: `team` 유지, 팀 null 프레임 0, 아군 조기 출전 0, 아머 잔류 0, 아군 피격 0.
